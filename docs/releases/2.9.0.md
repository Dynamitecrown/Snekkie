# Snekkie 2.9.0

Snekkie 2.9.0 adds file transfers and a two-pane file explorer over your SSH logins, side-by-side tabs in a grid, folders for saved sessions, and file tools for AI agents. Existing profiles and preferences carry over.

## File transfers

- **Right-click an SSH tab** to send or fetch a file beside the shell, with no second login. Snekkie uses SFTP where the device offers it and SCP otherwise, which is all many switches and routers speak.
- **File explorer:** a two-pane view of this computer and the server. Open it as an SFTP session type or with **Open file explorer** on an SSH tab, which shares that tab's login.
- **Queue:** three files move at once and the rest wait. Folders keep their structure. If a file already exists, Snekkie asks whether to **Overwrite**, **Skip** or **Keep both**. A partly uploaded file never replaces the original.
- **Manage files:** create folders, rename, delete and set permissions. Delete always shows how many files and folders it will remove, and Enter won't confirm it. Links are marked, and folder transfers and deletes don't follow them.
- **Edit server files:** **Edit** opens a private copy and uploads each save. If the file changed on the server too, Snekkie asks before replacing it. Snekkie won't open a file that would run as a program.
- **Choose your editor:** **Preferences → Files → Open with** picks the program **Edit** uses, such as your IDE. Otherwise your system's default app for the file type opens it.
- Names from a server that could write outside the chosen folder, or that Windows can't store, are skipped and shown in the queue.
- See [File transfers](https://github.com/Dynamitecrown/Snekkie/blob/v2.9.0/docs/file-transfers.md).

## Side by side

- Show up to eight tabs at once: four columns across, each holding one tab or two stacked. Terminals and file explorers can share the window.
- Drag a tab down out of the tab strip and over the workspace. The part it would fill lights up. Drop near a pane's edge to add it there, or in the middle to replace that pane or swap places with it.
- You can also right-click a tab and choose **Show side by side with**, or use **Open file explorer beside** on an SSH tab.
- Click a pane to give it the keyboard. A line along its top marks the active pane, and keys, paste and shortcuts go only there. Drag the dividers to resize.

## Saved-session folders

- Organize saved sessions into folders, up to six levels deep. Choose **…** > **New folder…**, then drag a session onto a folder or use its right-click menu.
- Folders can be renamed, moved and collapsed, and Snekkie remembers which are closed. Deleting a folder never deletes a session: what was inside moves up one level.
- The filter also matches folder names. Exports include each session's folder, and imports recreate it.

## AI agent file tools

- With the new **Let agents transfer and change files** setting, agents can list, read, write, upload, download, rename and delete files on connected SSH sessions and file explorer tabs, using the login already open.
- **Off by default, even with agent access on**, because these tools reach this computer's files as well as the server's. Agents with this on can read any file your account can and send it to a server.
- An existing file is replaced only if the agent passes `overwrite`. Deleting removes files, links and empty folders, never a whole tree in one call. Snekkie doesn't ask before an agent changes or deletes a file, so use your agent's own approval settings.
- On devices without SFTP, agents can read, write, upload and download over SCP. SCP can't check whether a file exists, so sending always needs `overwrite`, and a transfer that fails partway can leave a damaged file on the device.
- See [AI agent access](https://github.com/Dynamitecrown/Snekkie/blob/v2.9.0/docs/ai-agents.md#file-tools).

## Compatibility and verification

Saved profiles, themes, logging settings, snippets and paste controls remain compatible. If you save sessions in an older copy of Snekkie, it drops the folders, though the sessions themselves are kept.

Regression coverage uses in-process SSH servers offering SFTP, SCP or neither, and includes transfers, conflict prompts, editing with auto-upload, explorer drag and drop, the split grid, folders, the editor setting and the agent file tools.

Right-click transfers were tried against a real Proxmox server. The explorer, split view, folders, the native program picker, launching a real IDE, agent file tools called from a real agent, and SCP on real network devices still need checks on the systems where they are used.
