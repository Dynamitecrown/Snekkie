# Snekkie 2.8.0

Snekkie 2.8.0 lets AI agents on your computer work in the sessions you have open, refreshes the standard themes across the whole workspace, and fixes several security issues in profile import, SSH host-key checking, session logging and the in-app updater. Existing profiles and preferences carry over.

## AI agent access (MCP)

- An optional local Model Context Protocol server lets Claude Code, Claude Desktop, OpenAI Codex and self-hosted agents list your open tabs, read their output, type commands and answer prompts such as `--More--`.
- **Off by default.** Turn it on under **Preferences → Network**, which shows the exact command for this copy of Snekkie, with **Copy Claude Code command**, **Copy Codex command** and **Copy JSON config** buttons. Agents start `snekkie --mcp`.
- Agents can't open, close or reconnect sessions and never see passwords. Snekkie listens only on 127.0.0.1 with a fresh token for each run.
- You can see what an agent does: the tab and terminal glow cyan while it reads and amber while it types, and the status bar names the agent. Everything it types appears in the tab and in the session log. **Animate agent activity** chooses moving or steady cues, even while Animations is off.
- On Windows, a notification-area icon shows or quits Snekkie, starts or stops the agent server, and closes an agent's bridge, which can keep running after Snekkie closes.
- See [AI agent access](https://github.com/Dynamitecrown/Snekkie/blob/v2.8.0/docs/ai-agents.md).

## Workspace themes

- Standard themes now carry their colors through the terminal, sidebar, menus, dialogs and Preferences. Light themes use light controls and dark themes use dark controls, with a recessed terminal, neutral actions and thin accent lines on selected tabs and saved sessions.
- **Snekkie Dark**, **Paper Light**, **Frost Light**, **Copper Night** and **Forest Night** have revised palettes. Saved custom and named themes keep their stored colors, and the CRT, E-Ink, Blueprint and Amber appearances keep their monitor treatments.
- Saved-session rows show the alias above the protocol and destination, with serial device and baud rate; long lines shorten and the full destination is in the tooltip. **Host** and **Port** share a row, and short windows use tighter sidebar spacing.
- The empty workspace offers **New connection**. The README gains a feature overview, keyboard shortcuts and a settings and privacy summary.

## Security fixes

- **Profile import turns logging off.** Imported profiles no longer keep their log paths, so a shared profile file can't make device output write into one of your files. Each affected profile gets a note; choose a local log path with **Edit connection** to log it. Password logging stays off on import. Profiles already in your list are unchanged.
- **Revoked SSH host keys are refused.** `@revoked` entries in your `known_hosts` file are now checked before a key is trusted or you're asked about an unknown key, so before authentication. Matching covers host patterns, ports, IPv6 and hashed names. An unreadable or malformed trust file stops the connection rather than skipping the check.
- **Session logs can't grow memory without limit.** If a device sends more than 1 MiB without a line break, Snekkie stops logging that session with one warning, does not write the unredacted fragment, and keeps the connection open.
- **The in-app updater requires a verifiable installer.** It now refuses a release unless the installer comes from Snekkie's own GitHub release for that version and has a valid SHA-256 digest and a sane size, and it always checks the digest before running it.
- **Private logs on Linux and macOS.** New logs, raw input companions and rotated archives are readable only by you (mode 600), folders Snekkie creates for logs are private (700), and the default `logs` folder is made private whenever a log opens there. Files and folders you created elsewhere keep their permissions.
- Settings and profiles are saved through a unique temporary file each time, so two copies of Snekkie saving together can't mix or delete each other's file. The file that holds the agent server's port and token is readable only by you on Linux and macOS.

## Dependencies

- Updated rustls, rustls-webpki, webpki roots, crypto-bigint, ctutils, tokio, clipboard-win and yoke-derive to versions that resolve the RustSec advisories reported against them.
- A weekly `cargo audit` workflow now checks the lockfile. The reviewed exceptions, each with its reason, are the RSA timing advisory that has no fix (Snekkie signs only once per login with your own key) and unmaintained Linux accessibility crates used by the GUI toolkit.

## Compatibility and verification

Saved profiles, themes, logging settings, snippets and paste controls remain compatible. Regression coverage includes MCP access, agent activity cues, profile import with logging, SSH revocation matching and refusal before authentication, the logging line limit, updater release checks, Unix log permissions, concurrent settings saves and theme contrast for app controls. Visual checks used temporary settings and fictional local devices.

The notification-area icon, native file dialogs, physical serial hardware and real vendor devices still need checks on the systems where they are used.
