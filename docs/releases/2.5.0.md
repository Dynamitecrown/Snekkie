# Snekkie 2.5.0

Snekkie 2.5.0 adds terminal search, more ways to organize and transfer saved sessions, complete app themes, expanded syntax highlighting, and optional network privacy controls. Existing profiles and preferences carry over. Animations and automatic paging remain off by default.

## Find in terminal output

- **Ctrl+F** or **Edit → Find…** searches the current tab's screen and retained scrollback. Literal text is case-insensitive by default; **Match case** and **Regular expression** provide more precise searches. A short single-line selection prefills the query.
- **Enter** or **Previous match** moves toward older output; **Shift+Enter** or **Next match** moves toward newer output. Navigation wraps at either end, scrolls the result into view, and displays its position in the match count.
- On-screen matches are highlighted, with a stronger highlight for the current result. Colors work with standard, light, and monochrome themes. The bar adapts to narrow panes and moves away from results; in very small panes it can extend over the sidebar to keep output visible.
- Queries and options are separate for each tab. **Escape** or **Close search** hides the bar and restores terminal typing. Search input and navigation do not send keys to the device; Escape closes search even after focusing another search control or the terminal.
- Results refresh as output arrives, including when a query previously found nothing. Clearing history, resetting the terminal, or reconnecting removes old results while retaining the query.
- Matching joins soft-wrapped rows, supports wide and combining Unicode characters, ignores concealed text and ANSI escape codes, and searches a full-screen program's active screen. Large histories are scanned in batches to keep the app responsive. Search never changes copied text, exports, logs, or transmitted commands.

## Organize and transfer saved sessions

- Filter saved sessions by name, hostname/IP, serial device, or protocol. Star favorites and enable **Favorites only** to combine both filters. Favorites survive restart; older profiles start without a favorite.
- **Settings → Import → PuTTY sessions…** previews the current user's Windows PuTTY sessions or a UTF-16/UTF-8 `.reg` export. Select which SSH, Telnet, raw TCP, and supported serial profiles to import. Registry exports are parsed as text and are never applied to Windows.
- PuTTY import maps supported destinations, usernames, keepalives, serial settings, fonts, scrollback, local echo, and Backspace behavior. The preview explains skipped configurations and unsupported proxies, forwarding, remote commands, and `.ppk` keys. Passwords and host-key trust are excluded; key paths are references only.
- **Settings → Import → Snekkie profiles (.json)…** and **Settings → Export profiles…** transfer selected saved profiles through a preview. The sidebar's **…** menu opens the same workflows. Existing profiles are preserved, conflicting names receive unique suffixes, and importing never opens a connection.
- Profile exports include supported connection and terminal settings, favorites, tab colors, and key/log path references. Passwords, private-key contents, and host-key trust are excluded. Invalid or incompatible entries produce import notes, and protected active settings files cannot be overwritten by an export.
- Right-click a saved session to set its **Default tab color…**. Right-click an open tab to choose a temporary preset/custom color, clear its color, restore the profile color, or save the current choice as the profile default. Colors follow reordering and reconnecting; changing a profile default preserves temporary overrides on other tabs.

## Full app themes and new animations

- There are now **18 theme presets**, including **CRT Super**, **E-Ink Super**, **Blueprint Super**, and **Amber Super**. These style the menus, sidebar, controls, and terminal frame as a green monitor, matte reader, blue drafting instrument, or amber workstation.
- **Preferences → General → Theme colors → App appearance** lets custom themes combine an app appearance with editable colors. Monochrome output and CRT glow/scanlines are separate choices, and **Save as…** stores colors, appearance, and effects together. Returning to a standard preset restores its normal interface. Static theme effects work with animations off.
- New keystroke bursts include **Explosion**, **Lasers**, **Lightning**, and **Portal**. Typed characters gain **Stamp** and **Laser**; new text gains **Hologram** and **Binary decode**; new lines gain **Laser sweep** and **Radar pulse**.
- Each animation category remains independently configurable, with a master switch, speed control, and live preview. Particle counts remain bounded, drawing stays inside the terminal, and finished effects stop requesting frames. Effects do not change commands, clipboard text, exports, or logs.

## Expanded device highlighting and export formats

- Choose **Cisco IOS / IOS XE**, **Cisco NX-OS**, **Cisco ASA**, **Juniper Junos**, **Aruba AOS-CX**, **Arista EOS**, **Fortinet FortiOS**, or **Palo Alto PAN-OS** in a session's **Device** menu. Existing `cisco_ios` profiles continue to work; **None** retains original output colors.
- **Preferences → Highlighting → Intensity** applies five levels across all sessions: **Essential**, **Status**, **Commands** (the default), **Detailed**, and **Full**. Levels progress from validated IP addresses and security settings through prompts, protocols, commands, interfaces, MAC addresses, numbers, descriptions, and comments.
- A live preview compares platforms without changing a session. Applying the intensity recolors existing output; Cancel discards the draft. Monochrome themes take precedence over syntax colors. Highlighting is a display overlay and leaves commands, clipboard text, exports, and logs intact.
- Terminal save and append dialogs now offer **Plain text (.txt)**, **Cisco configuration (.cisco)**, **Markdown (.md)**, **Configuration (.cfg, .conf)**, **Log (.log)**, and **All files**. All formats retain the same UTF-8 plain-text capture behavior and support custom extensions.

## Network privacy and installation

- The Windows installer adds a **Network privacy** page. Preferences exposes the same choices to disable startup update checks or enable optional **Offline mode**. Existing installations preserve their choices during automatic updates.
- Offline mode disables startup/manual online update checks, update downloads, and application release links. Serial, localhost, and private/loopback/link-local IP connections remain available.
- Hostnames ask before using the system resolver. Each connection to a concrete non-local IP then requires **Allow once**, identifying the host, IP, and port. Approval is never saved; reconnects, duplicates, and fallback addresses ask again. IPv4-mapped IPv6 addresses use the underlying IPv4 classification.
- Enabling offline mode closes network sessions while leaving serial sessions available. Policy changes wait for any update operation to finish. Turning offline mode off does not automatically re-enable startup checks.
- Silent deployment supports `/OFFLINE`, `/NOUPDATES`, and `/ONLINE`. Without explicit privacy flags, upgrades preserve saved choices; `/UPDATE` skips the page and retains the policy.
- Privacy settings live in `network.ini` beside the user's settings and survive uninstall. An unreadable or damaged policy defaults to offline mode with updates disabled. Preferences also supports the policy on Linux; the installer page is Windows only.

## Logging status and documentation

- The active tab's status bar shows **Logging**, **Logging off**, or **Logging failed**, with the configured path or failure reason on hover. **Open log folder** opens the configured log's parent directory.
- Log open/write/flush failures are reported. A failed writer warns once and stops logging while terminal output and the connection continue; reconnecting retries the log. Logging remains appended raw received bytes.
- Added the [2.5.0 feature guide](../new-features.md), [syntax highlighting guide](../syntax-highlighting.md), current theme/highlighting/search screenshots, and a reproducible terminal-search screenshot example. Historical Python-release information is kept under `docs/archive/1.x/`.

## Updating and verification

- This is a full **2.5.0** release. Cargo metadata, the About dialog, Windows version resources, update checks, and packaging use the same version.
- Installed Windows copies can upgrade through the startup offer or **Help → Check for updates…**, when online updates are enabled. The updater uses `Snekkie-Setup-2.5.0.exe` and verifies its published SHA-256 before installation. Portable Windows and Linux copies retain their release-page download flow.
- Windows validation: **295 tests passed, 1 existing network release test ignored**; formatting, Clippy with warnings denied, the optimized application build, NSIS installer compilation, and search screenshot rendering passed. The executable and installer both report version **2.5.0**.
- Regression coverage includes search navigation and wire isolation, live output and cleared history, per-tab options, reset/reconnect, small-window theme layouts, imports and exports, favorites and tab colors, privacy enforcement, logging failures, highlighting, and animation rendering. The serial UI test waits for its final rendered error state to avoid a timing race.
- Release CI checks Windows and Linux, builds the Windows installer and portable executable plus the Linux tarball, and publishes these version-specific notes with the assets.
