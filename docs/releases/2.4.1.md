# Snekkie 2.4.1

Snekkie 2.4.1 fixes session-tab closing and session names being reused for a different destination. It also adds editing colors from any selected theme and a Ctrl+right-click terminal menu for copying, saving and appending output. Existing sessions, themes and preferences carry over. Animations and automatic paging remain off by default.

## Session fixes

- The small **X beside a session tab** now receives clicks reliably. Closing a connected session still asks for confirmation; cancelling leaves it open, and closing an inactive tab does not first switch to it. Closing the last tab, clicking tab titles, dragging tabs, middle-click closing and the tab's existing context menu continue to work.
- Starting another connection after loading or saving a named session no longer assigns that earlier name to a different host, protocol, network port or serial device. A changed destination gets its own host/port or device-based name. This also distinguishes different console-server ports while several sessions are open.
- Changing login details, fonts or serial speed preserves the saved alias for the same destination. Returning to the original destination restores its alias; saving the edited form under a new name associates that name with the new destination. Existing open tabs and the original saved profile are preserved.
- **New session** resets the form and clears the old saved-session selection.

## Edit any selected theme

- **Settings → Preferences → General → Theme colors** now lets you edit the **Text**, **Background**, **Cursor** and **Selection** colors of any selected preset or saved theme.
- The first color edit creates a Custom draft from the complete selected palette, preserving the colors you did not change and the original theme. The live previews show your edited palette.
- Use **Save as…** to give the edited theme a name. Reusing a saved name asks before replacing it; built-in theme names remain protected.
- **OK** applies and persists the theme. **Cancel** discards edits, including a replacement staged during that Preferences visit. Named custom themes load again on the next launch.
- Color pickers have accessible labels and consistent alignment.

## Terminal context menu and text files

Hold **Ctrl** and **right-click terminal output** to open these actions:

- **Copy** copies the selection; **Copy all** copies all retained output, including scrollback.
- **Paste**, **Select all**, **Clear selection** and **Scroll to bottom** provide the common terminal actions. Selection actions require a selection, Paste requires a live session, and Scroll to bottom is available while viewing history.
- **Save output to text file…** saves all retained output, including scrollback. **Save selection to text file…** saves only the selected text. Both use the native save dialog and write UTF-8 text.
- **Append to text file…** adds the selection, or all retained output when nothing is selected, to an existing file chosen through the native file picker. It preserves the file's existing contents and adds a line break between captures when needed. An empty selection does not append the entire history.

Copying and exporting do not change the scroll position or selection. Text extraction removes ANSI escape sequences, rejoins soft-wrapped rows, preserves wide and combining characters, and trims trailing blanks. Exports capture the text when the menu item is chosen, so later device output does not change that capture. Full-screen applications export their active screen rather than hidden shell history.

Plain right-click keeps its existing paste behaviour. Opening the context menu does not paste, and its navigation keys, Enter and Escape are not sent to the connected device. Choosing an action or pressing Escape returns focus for typing. Cancelling a file picker leaves files untouched; successful writes show a status message, and write failures show an error dialog. The context-menu gesture is also listed in **Help → Keyboard shortcuts**.

## Updating and verification

- This is a full **2.4.1** release, with matching Cargo metadata, application version information and packaging. The release workflow publishes these notes with the Windows installer, portable executable and Linux tarball.
- Installed Windows copies can update from **2.4.0** through **Help → Check for updates… → Update now**, or the update offered at startup. The existing updater requires the versioned `Snekkie-Setup-2.4.1.exe` asset and verifies its published SHA-256 before installing. Portable Windows and Linux copies retain their existing release-page download flow.
- Updated the README with the new controls and current installer examples.
- Added real application regression tests for tab closing, theme editing/saving/reloading/cancellation, multiple open sessions with changed destinations, and context-menu keyboard handling over a live TCP connection.
- Added emulator and menu tests for full scrollback, selections, soft wrapping, Unicode, export snapshots and unchanged scrolling, plus file tests for UTF-8 saves, cancellation, append separators, existing-content preservation and write errors.
- Windows validation: **216 tests passed, 1 existing network release test ignored**; formatting, Clippy with warnings denied and compilation passed. Release CI also runs Linux checks and platform-specific tests before publishing.
